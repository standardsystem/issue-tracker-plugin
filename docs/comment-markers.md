# 課題に残すコメントの印

スキル `/resolve-issue` は、段階ごとに課題へコメントを残します。
コメントの1行目は `[resolve-issue] <印>` とし、2行目から詳しく書きます。

印は、人が読むためだけのものではありません。スキルは、次に着手するときに最新の印を読み、その課題を作業中とみなすか、続きから再開できるかを決めます。
そのため、印の文言はこの一覧のとおりに書きます。変えるときは、書式の番号と同じように扱い、CHANGELOG に書きます。

## 一覧

| 印 | いつ残すか | 本文に書くこと | 次の着手の確認での扱い |
| --- | --- | --- | --- |
| `着手` | 状態を着手（`inProgress`）にしたとき | ブランチ名、作業ツリーの場所、元のブランチ | 作業中 |
| `PR を作成` | PR を出したとき | PR の URL、PR を作ったときの head のコミット | 作業中 |
| `レビュー n 回目` | レビューの結果を PR に投稿したとき | レビューした者、重大度ごとの件数 | 作業中 |
| `マージ` | マージしたとき | マージコミット | 作業中 |
| `確認待ち` | 公開か本番での確認を残して止めたとき | 残っている段階（`公開` か `本番での確認`）、確かめることと、その方法 | 再開できる（残っている段階から） |
| `リリース待ち` | 公開の型が `release` で、マージまで終えたとき | 次のリリースのあとで確かめること | 再開できる（リリースが出たことを確かめてから） |
| `止まった` | 着手のあとで、利用者の答えを待つとき（マージの承認、公開の失敗、3回目のレビューでも P0・P1 が残った、など）。聞く前に残す | 止まった段階、理由、決めてほしいこと、ブランチ、PR、作業ツリーの場所（マージの承認なら head のコミット）。利用者がやめたときは、そのこと | 利用者の答えがあれば再開できる |
| `完了` | 状態を完了（`done`）にしたとき | 確かめたこと | 着手しない。ただし状態が完了扱いでなければ、開き直された課題として、新しく着手するかを利用者に聞く |

例:

```markdown
[resolve-issue] PR を作成

https://github.com/acme/tasks-web/pull/42
head: 3f2c1ab
```

```markdown
[resolve-issue] 確認待ち

残っている段階: 本番での確認
- スマホのブラウザで、一覧の並べ替えが効くこと（ログインが要るので利用者に頼む）
```

## 着手の確認での扱い

- **作業中**: 別の人やセッションが作業しているものとみなし、着手しない。
  利用者には、最後のコメントの日時と PR の状態を添えて伝え、「続きから再開するか、外すか」を選んでもらう。
  セッションが途中で終わって放置された課題も、印からは見分けられないので、時間がたっていても自動では再開しない。
  別の人が長く作業している課題を、横取りしないためである。
- 利用者が「続きから再開」を選んだときは、最新の印の段階から続ける。状態は変えず、新しいブランチも切らない。
- **再開できる**: 最新の印の段階から続ける。`/resolve-issues` は、これらの課題を新しく着手する候補に混ぜず、「確認を再開できる課題」として別に示す。
- 状態が着手（`inProgress`）かマージ済み（`merged`）なのに印の付いたコメントが無い課題は、人が手で作業しているものとみなし、作業中として扱う。
