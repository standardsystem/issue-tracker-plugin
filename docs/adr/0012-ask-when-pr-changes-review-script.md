# ADR 0012: PR がレビューのスクリプトを変えたときは、差分を示して、Codex に送ってよいかを利用者に確かめる

- **Status**: Accepted
- **Date**: 2026-11-23
- **Deciders**: kazuyukikato
- **Related**: [ADR 0008](0008-check-review-config-before-starting.md)（この ADR が一部を改める）、[ADR 0009](0009-show-all-review-config-problems-at-once.md)（送ってよいという答えを残す）、[ADR 0005](0005-review-model-and-multiple-reviewers.md)

## Context

ADR 0008 で、`## レビュー` の呼び方が作業するリポジトリの中のスクリプトを呼ぶときは、送ってよいかを聞かずに、その呼び方に従うと決めた。
そのリポジトリにスクリプトを置いた人が、送る範囲を決めているためである。スクリプトがあることと渡し方は、着手の前に、既定のブランチの文面で確かめる。

一方、レビュー（5 章）では、PR の head を取り出した作業ツリーで、head のスクリプトが動く。そのため、次のことが起きうる。

1. 課題の変更が、レビューのスクリプトを変えて送る範囲を広げると、変えたスクリプトがそのまま動く。利用者が確かめないまま、広げた範囲が Codex へ送られる。
2. 既定のブランチの文面で決めた渡し方（作業ツリー・依頼文・結果）と、head のスクリプトの引数がずれる。

聞かずに従う理由は「既定のブランチに入ったスクリプトが範囲を決めている」ことなので、PR が変えたスクリプトには当たらない。外に送ったものは取り消せない。

## Decision

- **PR がレビューのスクリプトを変えていたら、レビューを動かす前に止まり、差分を示して、送ってよいかを利用者に確かめる。**
  `review.by` に `codex` があり、呼び方が作業するリポジトリの中のスクリプトを呼ぶときに、回ごとに（2 回目以降も、再開したときも）見る。指摘への対応で、スクリプトが変わることがあるためである。
  複数の者を並べたときも、誰のレビューも動かす前に見る。
- **見るのは、呼び方が呼ぶスクリプトと、`## レビュー` に、送る範囲を決めるファイルとして書いてあるものである。**
  スクリプトが範囲をほかのファイル（送るファイルの一覧など）から読むことがある。スキルはスクリプトを動かさず、中身も解釈しないので、そのファイルは `## レビュー` に書いてもらう。
- **変えたかは、PR の差分（`git diff origin/main...<head> -- <パス>`）で見る。** head のファイルが今の既定のブランチのものと同じなら、変えていないものとする。
  既定のブランチに入ったものを取り込んだだけのとき（再開のときに、スクリプトだけを PR のブランチにコミットした、など）に、聞かないためである。
- **範囲が広がったかは、スキルが判断しない。** 変えていれば、どんな変更でも聞く。判断するのは、差分を見た利用者である。
- **送ってよいという答えは、課題の、印の付かない記録のコメントに残す。** 作業するリポジトリ、変えたファイル、答えを受けた head のコミットを書く。
  答えは、示した head のファイルにだけ効く。記録したコミットからそのファイルが変わっていなければ、あとの回でも再開でも聞き直さず、変わっていれば聞き直す（ADR 0009 と同じ考え）。
- **送ってよいと答えたら、head のスクリプトで動かす。** 渡し方をスクリプトの文面で決めていたときは、head の文面で決め直す。決まらなければ、使えないものとする。
- **送ってはいけないと答えたら、止めたままにする。** 選べるのは、スクリプトの変更を PR から外す（別の PR に分けて、先に既定のブランチに入れる）、レビュー無しでマージへ進む（マージの直前に承認を受ける）、やめる、のどれかである。
  `codex` の代わりに `claude` でレビューしない（ADR 0005・0008 と同じ理由）。

## 検討した代替案

- **既定のブランチのスクリプトを、head の作業ツリーに向けて動かす。** 聞かずに済み、変える前の範囲で送れる。しかし、次の理由で採らない。
  - スクリプトを、置き場所の外に取り出して動かすことになる。自分の場所からの相対パスや、隣のファイルを前提にしたスクリプトは動かない。
  - 範囲をほかのファイルから読むスクリプトでは、そのファイルは head のものが読まれるので、範囲は守れない。
  - PR がスクリプトと一緒にファイルの配置を変えていると、古いスクリプトの範囲や引数が head と合わない。足りないレビューが、気づかないまま通りうる。
- **今までどおり、聞かずに head のスクリプトで動かす。** 手間は無いが、Context の 1 が残る。
- **差分を読んで、範囲が広がったときだけ聞く。** 聞く回数は減るが、スクリプトの書き方は決まっておらず、広がったかをスキルが確かに判断できない。誤って「広がっていない」と読むと、確かめないまま送る。変えていれば聞くほうに倒す。
- **変えていたら、レビューを飛ばすか、`claude` で代える。** 設定と違う者のレビュー、または足りないレビューで先へ進むことになる（ADR 0005・0008）。
- **答えを残さず、セッションの中でだけ覚える。** 再開のたびに聞くことになる。外に送るものの許しは、記録に残るほうが確かめやすい（ADR 0009）。

## Consequences

- レビューのスクリプトを変える PR は、変えた内容ごとに1回、レビューの前に止まる。送る範囲を変える変更を、ほかの変更と分けて先に既定のブランチに入れれば、止まらない。
- スキルが気づくのは、呼び方が呼ぶスクリプトと、`## レビュー` に書いてあるファイルの変更だけである。範囲を決めるファイルを `## レビュー` に書いていなければ、その変更には気づけない。
- PR が設定のファイル（`## レビュー` の呼び方や、送ってよい範囲の文）を変えたときのことは、この ADR では決めていない。
- 範囲を狭める変更や、範囲に関わらない変更でも聞く。
- 設定のファイルの書式の番号と、コメントの印の文言は変えない。印の付かない記録が1つ増え、`止まった` の本文に書くことが増える。
