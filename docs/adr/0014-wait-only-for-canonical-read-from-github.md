# ADR 0014: レビューの設定を直したあと、既定のブランチに入るのを待つのは、GitHub から読んだ正本のときだけにする

- **Status**: Accepted
- **Date**: 2026-11-24
- **Deciders**: kazuyukikato
- **Amends**: [ADR 0008](0008-check-review-config-before-starting.md)（正本を直したときは、既定のブランチに入ってから続ける）
- **Related**: [ADR 0010](0010-repo-only-config-for-public-repositories.md)（リポジトリの層だけのファイル。このときに、書式の文書で「正本」を定義し直した）、[ADR 0013](0013-read-settings-from-default-branch.md)（手元のリポジトリの設定のファイルを読む場所）

## Context

ADR 0008 は、レビューの設定の誤りで止まったあと、「正本のファイルは GitHub の既定のブランチから読むので、正本を直したときは、既定のブランチに入ってから続ける」と決めた。
このときの「正本」は、`definedIn` で指した先のファイルだった。

そのあと、0.11.0（ADR 0010 のとき）で、書式の文書の「正本」を「作業に使うプロジェクトの層を書いたファイル。`definedIn` で指した先か、作業を始めたリポジトリのファイル」と定義し直した。
正本の読み方は、次の2通りになった。

| 作業を始めたリポジトリ | 正本 | スキルが読む場所 |
| --- | --- | --- |
| `definedIn` があるリポジトリ | 指した先のリポジトリのファイル | GitHub の既定のブランチ |
| プロジェクトの層を自分で持つリポジトリ | 作業を始めたリポジトリのファイル | 手元にあるリポジトリ（ADR 0013 のとおりに読む） |

しかし、止まったあとの続け方は、どちらの正本でも「既定のブランチに入ってから続ける」と読める文面のままだった。
手元のファイルが正本のときは、手元を直せばスキルは読み直せる。それなのに、直しを PR にしてマージするまで、課題の作業を続けられないことになる。理由の「GitHub の既定のブランチから読む」も、この場合には当たらない。

ADR 0013 は、手元にあるリポジトリのファイルの読み方を決め、スキルの文面も、手元のファイルと `definedIn` の先のファイルに分けて書き直した。
ただし、書式の文書には古い文が残り、手元のファイルが正本のときにどちらに当たるかは、文面に明記していなかった。

## Decision

- **既定のブランチに入るのを待つのは、GitHub から読んだ正本（`definedIn` で指した先）のときだけにする。**
  手元のファイルが正本のときは、作業するリポジトリのファイルと同じに扱う。手元の作業ツリーが既定のブランチなら、コミットせずに直せば、待たずに続けてよい。
- **手元の作業ツリーが既定のブランチでないとき（再開して、課題のブランチになっている、など）は、手元のファイルが正本のときも、直しが既定のブランチに入ってから続ける。**
  ADR 0013 の読み方を、正本にもそのまま当てる。課題のブランチで変えた設定を、既定のブランチに入る前に効かせないためである。
- **未コミットの直しを読んで先へ進むときは、直しを既定のブランチに入れるよう、利用者に伝える。** 伝えるだけで、答えは待たない。
  直しが効くのは、既定のブランチの作業ツリーに未コミットのまま残っている間だけである。コミットしただけで push していない直しは読まれない（ADR 0013）ので、「コミットして残す」とは伝えず、「既定のブランチに入れる」と伝える。
- **スキルと書式の文書では、続け方を、直すファイルを読んだ場所の2通りに分けて書く。** 正本がどちらに当たるかも書く。

## 検討した代替案

- **待つのは残し、理由を「直しを既定のブランチに残すため」に変える。** 直しが未コミットのまま残ることは防げるが、手元を直せば読めるのに、PR をマージするまで続けられない。
  作業するリポジトリのファイルは待たずに続けられるので、正本のときだけ待つ理由が無い。直しを残すことは、伝えることで補う。
- **何もしない。** 文面が「正本」の定義と食い違ったままになり、スキルを動かすエージェントが、どちらに当たるかを迷う。
- **手元の作業ツリーが既定のブランチでないときも、手元のファイルが正本なら、直しをすぐ読む。** 待ち時間は無くなるが、課題のブランチやほかのブランチのファイルを読むことになり、ADR 0013 で防いだこと（課題の変更で変えた設定が、既定のブランチに入る前に効く）が、正本でだけ起きる。

## Consequences

- プロジェクトの層を自分で持つリポジトリ（1つのリポジトリだけのプロジェクトと、正本のリポジトリで始めたとき）では、正本の設定の誤りを、既定のブランチの作業ツリーで直せば、同じセッションで続けられる。
- ADR 0008 の Consequences の「正本の設定に誤りがあるときは、直しが正本の既定のブランチに入るまで、そのプロジェクトの課題に着手できない」は、`definedIn` で指した正本にだけ当たる。
- 未コミットの直しで続けたあと、直しを既定のブランチに入れないままにすると、コミットしたときやブランチを切り替えたときに、直す前の設定が読まれる。スキルは、続けるときにそのことを伝える。
- 設定のファイルの書式の番号と、コメントの印は変えない。
