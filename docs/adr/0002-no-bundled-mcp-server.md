# ADR 0002: MCP サーバーの接続の設定をプラグインに含めない

- **Status**: Accepted
- **Date**: 2026-11-06
- **Deciders**: kazuyukikato
- **Related**: [ADR 0001](0001-plugin-and-project-config.md)（「配り方」の MCP の部分を、この ADR で変える）

## Context

ADR 0001 では、プラグインに MCP サーバー `issue-tracker` への接続の設定を含め、接続先と API キーを環境変数から読むとしていた。
実装する前に Claude Code の文書と Issue Tracker の仕様を確かめたところ、次のことが分かった。

- Issue Tracker の API キーは、操作できるプロジェクトを絞って発行できる。利用者は今、各リポジトリの `.mcp.json`（Git の対象外）に、そのプロジェクト用に絞ったキーを書いている。
- プラグインに含めた MCP サーバーの設定は、プラグインに1つだけである。キーは環境変数か、プラグインを有効にするときの入力（`userConfig`）で1つ渡すことになり、すべてのプロジェクトで同じキーを使う。
  範囲の広いキーを勧める形になり、漏れたときの影響が大きくなる。
- 環境変数が未設定でも設定は読み込まれ、`${VAR}` がそのまま残った誤った URL になる。
- リポジトリの `.mcp.json` に同じ接続先のサーバーがあると、リポジトリの設定が優先されるとみられる。しかし、二重に読み込まれないかは確かめていない。

## Considered Options

- **A. 含めない。** 利用者は今までどおり、各リポジトリの `.mcp.json` で設定する。
- **B. 含める。** 接続先と API キーを `userConfig` で受け取る。

## Decision

**A を採用する。**

- MCP サーバーの設定は、利用者が各リポジトリの `.mcp.json` に書く。書き方は README に載せる。
- スキルは最初に、MCP サーバー `issue-tracker` のツールが使えるかを確かめる。使えなければ止めて、README の設定の手順を案内する。
- スキルは MCP のツールを、`get_issue` のような短い名前で指す。どこで設定したサーバーでも同じ手順で使えるようにするためである。

## Consequences

良い点:

- プロジェクトごとに範囲を絞った API キーを、そのまま使える。
- すでに `.mcp.json` を設定している利用者は、プラグインを入れるだけで使える。設定が二重になることもない。
- プラグインが接続先を知らないので、公開のリポジトリに接続先の手がかりが入らない。

注意する点:

- プラグインを入れただけでは使えない。リポジトリごとに `.mcp.json` を設定する手間が残る。
- 利用者が `.mcp.json` を Git に入れないよう、README で注意する。
