# ADR 0005: レビューする Claude のモデルを設定で選び、複数のレビューする者を並べられるようにする

- **Status**: Accepted
- **Date**: 2026-11-13
- **Deciders**: kazuyukikato
- **Related**: [ADR 0001](0001-plugin-and-project-config.md)（レビューは既定で Claude の別のエージェントにさせ、ほかは設定で選ぶ）

## Context

あるスキルの変更を、Codex と、モデルを指定した Claude の別のエージェントの2つで並べてレビューしたところ、重なった指摘は少なく（27 件中3件、18 件中2件）、互いの見落としを補い合った。
Codex は少数の重大な指摘に絞り、Claude のほうは網羅的で、git の挙動を使い捨てのリポジトリで確かめて P1 を見つけた。

今の書式では、`review.by: claude` のエージェントのモデルを選べず、レビューする者を1つしか選べない。Codex を使わないチームでも、別のモデルの目を入れられるようにしたい。

## Decision

1. **`review.model` を足す。** `by` の `claude` のエージェントのモデルを選ぶ。省略すると指定なし（呼び出し元と同じ）。値は起動時のモデルの指定にそのまま渡し、プラグインは値の一覧を持たない（使える値は環境で変わるため）。
   起動できなければ、指定なしで代わりに動かさず、失敗として止まる。設定と違うモデルのレビューを、気づかないまま通さないためである。
2. **`by` に一覧を書けるようにする。** 並べた全員が同じ head をレビューする。
   - 全員の結果がそろってから仕分ける。一人でも得られなければ、得られた者だけでは進まず止まる（欠けた者の目が、承認なしのマージの根拠から黙って抜けないようにする）。
   - 同じファイルの同じ箇所に、同じ原因と影響を挙げた指摘は1件にまとめ、重大度は高いほうを取る。迷うときはまとめない（見落としより、重複のほうが害が小さい）。
   - 回数（最大3回）は1巡を1回と数え、件数はまとめたあとの件数とする。数え方は者の数で変わらない（者を足すと正しい P0・P1 が出やすくなり、止まりやすくなる）。
   - 同じ者は2度並べない。`none` は並べない。モデルを変えた `claude` の2つ並べは、今は作らない（`review.model` が1つだけのため）。必要になったら、`by` の要素にモデルを書く形を検討する。
3. **`review.model` だけなら書式の番号は 1 のまま、一覧を書くときは `format: 2`。** `review.model` は古いスキルに無視されても、呼び出し元と同じモデルでレビューが行われるだけである。一覧は、古いスキルが黙って1人分に読み替え、足りないレビューのまま承認なしでマージに進むおそれがあるため、番号を上げて古いスキルを止める。1 のファイルは新しいスキルがそのまま読める。一覧に `none`・重複・空・知らない値があるときは、着手の前に止まる。版は 0.5.0 に上げる。

## Considered Options

- **`by` を `claude:fable` のように書く。** 一覧と1つにまとまるが、`by` の値の形が変わり、`codex` の版の指定と書き方が揃わない。
- **全員の結果を待たず、先に返った者から進める。** 速いが、遅い者の指摘が承認なしのマージの後に出ることがある。

## Consequences

- モデルの違う目を、Codex なしでも入れられる。複数を並べると、レビューの時間と費用は者の数だけ増える。
- 0.5.0 より古いスキルは、`review.model` と一覧を読まない。使うチームはスキルを更新する。
