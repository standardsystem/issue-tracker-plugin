# ADR 0004: 正本の Markdown の節は、`## レビュー` だけを受け継ぐ

- **Status**: Accepted
- **Date**: 2026-11-08
- **Deciders**: kazuyukikato
- **Related**: [ADR 0001](0001-plugin-and-project-config.md)（設定のファイルを、プロジェクトの層とリポジトリの層に分けた）

## Context

設定のファイルの書式は、YAML の値について「そのリポジトリの `repo` → 正本の `project.defaults` → スキルの既定値」の順を決めている。
一方、Markdown の節（`## 確認`・`## レビュー`・`## 公開と確認`・`## 毎回確かめること`・`## そのほか`）を正本から受け継ぐかは、`## 毎回確かめること`（0.2.0 から両方を見る）のほかは決めていなかった。

複数のリポジトリにまたがるプロジェクトで、Codex の呼び方と版を正本の `## レビュー` に書いても、ほかのリポジトリには効かなかった。
各リポジトリに「正本の `## レビュー` のとおり」と1行書いて補っていたが、書式に無い読み方に頼っており、書き忘れると版の指定が黙って効かなくなる。

## Considered Options

- **A. すべての節を受け継ぐ。** 作業するリポジトリに同じ節があれば、それで置き換える。
- **B. 節ごとに決める。** `## レビュー` だけを受け継ぎ、作業するリポジトリの節と合わせて読む。
- **C. 受け継がない。** 今のまま、各リポジトリに書く。

## Decision

**B を採用する。**

| 見出し | 正本の節 | 理由 |
| --- | --- | --- |
| `## レビュー` | 受け継ぐ。正本の節を読んでから作業するリポジトリの節を読み、食い違えば作業するリポジトリを優先する | Codex の呼び方・版・送ってよい範囲は、プロジェクト全体で決めることである。正本の1か所で版を上げれば、どのリポジトリにも効く |
| `## 毎回確かめること` | 両方を見る（0.2.0 から変えない） | 確かめることが増えるだけで、安全な側に倒れる |
| `## 確認` | 受け継がない | 確かめ方は、リポジトリの技術の組み合わせで変わる |
| `## 公開と確認` | 受け継がない | 正本の公開の手順や本番での確かめ方を、ほかのリポジトリに当てるおそれがある。節が無ければ、スキルが利用者に聞く |
| `## そのほか` | 受け継がない | スキルが分岐に使わない注意で、受け継ぐ必要が見つかっていない |

`## レビュー` を、作業するリポジトリの節で置き換えにしないのは、リポジトリに「指摘しなくてよい書き方」を1行書いただけで、正本の「送ってよい範囲」が外れるのを防ぐためである。

A は、`## 公開と確認` を受け継ぐ危うさがある。C は、今の書き忘れの危うさが残る。

## Consequences

良い点:

- Codex の呼び方・版・送ってよい範囲を、正本の1か所に書けばよい。
- 送ってよい範囲のような、外に送る情報を絞る決まりが、リポジトリの節で落ちない。

注意する点:

- 正本の `## レビュー` に正本のリポジトリだけのことを書くと、ほかのリポジトリのレビューにも渡る。書式で、そうと分かるように書くよう求める。
- 今ある正本の `## レビュー` の意味が変わる。CHANGELOG に書く。書式の番号は、今あるファイルがそのまま読めるので 1 のままにする。
