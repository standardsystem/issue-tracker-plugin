# ADR 0006: 作業している間だけ課題を予約し、止めるときは解除する

- **Status**: Accepted
- **Date**: 2026-11-14
- **Deciders**: kazuyukikato
- **Related**: [comment-markers.md](../comment-markers.md)、[ADR 0003](0003-review-gated-merge.md)

## Context

Issue Tracker のサーバーに、課題の着手の予約が入った。MCP のツールは次の2つである。

- `reserve_issue`: 予約か延長をする。期限は既定で 60 分、最長で 24 時間。
- `release_issue_reservation`: 予約を解除する。

予約の振る舞いは次のとおりである。

- 有効な予約がほかにあれば、同じ API キーからでもエラーになり、その予約の持ち主・期限・メモを返す。
- 延長と解除には、予約したときに返る `reservationId` が要る。サーバーは、持ち主でない人が延長・解除できないよう、`get_issue` ではこの ID を返さない（今の予約の持ち主・期限・メモは `get_issue` の `reservation` で見られる）。
- 予約しても、課題の状態・担当者・履歴は変わらない。

MCP サーバーの instructions は、複数のセッションで並行して着手するときは予約するよう求めている。0.6.0 までのスキルは予約を使っていなかった。
そのため、2 つのセッションで同時に `/resolve-issues` を動かすと、同じ課題を選び、どちらも `着手` の印を残す前に着手しうる。

スキルには、すでにコメントの印がある。最新の印が `着手` などの課題は作業中とみなし、`止まった`・`確認待ち` などの課題は、利用者の答えを確かめてから再開する。
印は、一度残せば、ほかのセッションが同じ課題を新しく始めるのを防ぐ。防げないのは、着手の確認から `着手` の印を残すまでの間と、印の無いまま作業する人やエージェントである。

## Decision

- **2 章の初めと、再開して続きの段階へ進む前に予約する。** 止めたあと同じセッションで利用者の答えを受けて続けるとき（マージの承認のあとなど）も、続ける前に新しく予約する。
  予約できなければ、着手も続きもせず、状態も印も変えない。どの時機も前の印から作業が進んでいないので、`確認待ち`・`リリース待ち` の印を `止まった` で上書きしない。同時に予約しようとしたというエラーだけは、1回呼び直す。
  1 章でも、`get_issue` の `reservation` があれば着手しない。
- **状態が完了扱いの課題は、予約せずに進む。** マージ済みの状態が完了扱いのプロジェクトでは、8・9 章へ続けるときに、サーバーが予約を受け付けない。
  この課題は、印がほかのセッションの新しい着手を防ぐ。2 つのセッションが同じ `確認待ち`・`リリース待ち` から同時に再開することは防げないが、0.6.0 までと同じなので受け入れる。
- **期限は既定の 60 分にし、3〜9 章の各章の初めに延ばす。** 長い章では、期限の前に途中でも延ばす。
- **このセッションでこの課題の作業を終えるときは、予約を持っていれば解除する。** 完了、`確認待ち`・`リリース待ち`・`止まった` の印を残したとき（同じセッションで答えを待つときも）が当たる。解除に失敗しても、期限で切れるので、伝えて進む。
- **`reservationId` は、セッションの中でだけ控え、印のコメントにも PR にも書かない。**
- **延長に失敗したら止まる。** 予約をもう持っていないというエラーなら、予約はほかのセッションのものなので、解除しない。ほかのエラー（課題が閉じられた、など）なら、まだ持っているかもしれないので解除する。
- **`note` には、スキルの名前を書き、ブランチが決まったら（再開では `着手` の印のブランチ）ブランチ名を足す。** 課題キーや社内の情報は、このリポジトリの例に書かない。
- **予約のツールが無い古いサーバーでは、予約せずに進む。**

## 検討した代替案

- **`reservationId` を `着手` の印に書き、再開したセッションが延長・解除する。** コメントはプロジェクトの誰でも読めるので、持ち主でない人も延長・解除できてしまう。サーバーが ID を `get_issue` で返さない方針と合わない。
  前のセッションが途中で終わって予約が残ったときは、期限（最長 60 分）が切れるのを待てば、新しく予約できる。
- **止めたときも予約を残す。** 利用者の答えは、何時間も来ないことがある。予約を残すには長い期限が要り、セッションが途中で終わると、その間は誰も再開できない。
  止めた課題は、`止まった` などの印がほかのセッションの着手を防ぐので、予約を残さなくてよい。
- **期限を長く（数時間）取り、延長しない。** 延長の手間は減るが、途中で終わったセッションの予約が長く残る。
- **予約だけにして、印をやめる。** 予約には、どこまで進んだか（ブランチ、PR、待っていること）が残らない。再開に要るのは印である。

## Consequences

- 2 つのセッションが同じ課題を選んでも、先に予約したほうだけが着手する。後のほうは、`resolve-issues` ではその課題を外して次へ進む。
- 前のセッションが途中で終わると、その予約が切れるまで（最長 60 分）、その課題は再開できない。
- `list_issues` には予約が出ないので、`resolve-issues` の候補の表には、ほかのセッションが予約している課題も出る。着手の直前の確認と予約で外れる。
- 延長のたびに MCP のツールを1回呼ぶ。1件あたり、章の数（7 回）ほど増える。
