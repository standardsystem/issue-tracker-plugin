# レビューの依頼文の型

レビューする者（Claude の別のエージェント、Codex）は、この会話を知らない。要ることは、すべて依頼文に書く。
`<…>` を埋めて使う。

```markdown
<owner>/<repo> の PR #<番号>（base は origin/<既定のブランチ>、head は <コミット>）をレビューしてください。
リポジトリの場所: <絶対パス>

## してはいけないこと

- ファイルを変更しない。コミットしない。ブランチや作業ツリーの状態を変えない。
- GitHub に投稿しない（結果は、この依頼への返答として返す）。

## 調べ方

- 最初に `git -C <絶対パス> rev-parse HEAD` が <コミット> と一致することを確かめる。違えば、レビューせずにそのことを報告する。
- 差分は `git -C <絶対パス> diff origin/<既定のブランチ>...<コミット>` で見る。
- リポジトリの指示は `AGENTS.md`（無ければ `CLAUDE.md`）にある。先に読む。
- 呼び出し元と、関連する仕様も読む。変更によって入った不具合と回帰に絞る。
- 外部のサービスの、確かめていない挙動を事実として断定しない。

## この PR の目的

- 課題: <課題キー> <件名>
- やること: <課題の「やること」>
- 関連する仕様: <ファイルの場所>

## 意図してしていること（指摘しなくてよい）

- <例: 下書きにしている理由など。無ければ「なし」>

## 返し方

指摘ごとに、次を書く。

- 重大度: `[P0]`〜`[P3]`
  - P0・P1: 不具合、セキュリティ、仕様違反
  - P2: 直すべき軽い問題
  - P3: 好み
- ファイルと行
- 発生する条件と影響
- 直し方

最後に、重大度ごとの件数と、実行した確認（コマンドと結果）、確かめられなかった範囲を書く。指摘が無ければ、その旨と確かめた範囲を書く。
```

## 2回目から足すこと

```markdown
## 前回の指摘への対応

| 指摘 | 対応 |
| --- | --- |
| <前回の指摘の要旨> | 直した（<コミット>） / 直さない（<理由>） |

直さないとした指摘は、理由が誤っているときだけ、もう一度指摘してください。
```
